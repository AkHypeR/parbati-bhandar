# Parbati Bhandar Android apps

Two separate Android apps are maintained here:

- `customer/` — customer storefront app.
- `owner/` — private owner management app.

Both are lightweight Android WebView shells around the existing HTTPS website. This intentionally reuses the current Cloudflare Pages Functions and D1 database instead of creating a second order, customer, product or inventory system. The website remains unchanged and can continue to be used normally.

## Build each APK

Run the commands from the relevant app directory:

```bash
cd mobile/customer
npm install
npm install --global eas-cli
eas login
eas build:configure
npm run build:apk
```

Repeat from `mobile/owner` for the owner APK. Each app has its own Android application ID, Expo project link and signing identity. A successful EAS cloud build produces an installable APK download link.

## Before distributing

1. Confirm the live storefront URL and update `EXPO_PUBLIC_STORE_ORIGIN` if the production domain differs.
2. Test customer registration/login, cart, checkout and order tracking in the customer APK.
3. Test owner login, dashboard routes, orders, inventory, image upload, settings and backup/restore in the owner APK.
4. Verify Android back navigation, WhatsApp handoff and offline/retry behaviour.
5. Do not test restore against the live production database. Use a separate test database.
6. Distribute the owner APK privately only to the authorised store owner. Do not publish it as a public customer app.

## Build status

Source code and APK build profiles are committed separately from the website. APK files are not generated by the website's Cloudflare Pages deployment. EAS account setup and a cloud build are required before installable APK files exist.
